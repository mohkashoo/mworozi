Build "Project Humura" — a neonatal cry diagnostic triage platform for rural African midwives.

## Architecture
Two-tier pipeline:
- Tier 1 (local): librosa feature extraction + scikit-learn Random Forest → classifies cry as normal (0) or distress (1)
- Tier 2 (cloud): Google Gemini generates structured clinical brief when distress detected. Falls back to rule engine if API key missing.

## Files to create

### 1. audio_processor.py
- NeonatalAudioEngine class
- 36 acoustic features: f0_mean/std, spectral_centroid_mean/std, 13 MFCCs (mean+std), bandwidth_mean/std, rolloff_mean/std, zcr_mean/std, rms_mean/std
- Feature extraction using librosa.yin + librosa.feature.*
- On init: load pre-trained model from cry_model.joblib if exists, else train from scratch on synthetic data
- Synthetic training: generate 150 normal cries (350-600 Hz, stable) + 150 distress cries (600-900 Hz with pitch breaks, high spectral energy) using numpy sine waves + envelope + noise
- Random Forest: 200 trees, max_depth=16, class_weight="balanced", random_state=1
- evaluate_cry(audio_buffer) → dict with classification, probability (probs[1]), risk_score (probability*95+5), anomaly_score, features
- compute_spectrogram(audio_buffer) → spectrogram dB + f0_track for Plotly
- generate_simulated_cry("normal" or "distress") → WAV bytes

### 2. app.py — Streamlit clinical dashboard
- Dark theme: background #090a0f, cards #0f1520, emerald #10b981, red #ef4444
- Bootstrap Icons CDN: https://cdn.jsdelivr.net/npm/bootstrap-icons@1.11.3/font/bootstrap-icons.min.css
- Page config: wide layout, title "Project Humura — Neonatal Cry Triage"
- Cache the engine with @st.cache_resource
- Sidebar: patient form (name, age_days, temperature, heart_rate, respiratory_rate, weight, maternal_history) + audio source segmented_control (🎤 Live Mic / 📁 Upload Audio / 🧪 Simulated Profile)
- Live Mic uses st.audio_input, Upload uses st.file_uploader, Simulated has 3 profiles: Normal Discomfort Cry / High-Risk Asphyxia Marker / High-Risk Respiratory Distress
- Main area: title bar with bi-heart-pulse-fill icon, then analysis results
- On "Run Triage Analysis" click: validate inputs → evaluate_cry → compute_spectrogram → determine risk (CRITICAL 80+ / HIGH 50-79 / MODERATE 41-49 / STABLE 0-40) → if HIGH+ call Gemini or rule engine fallback → save to SQLite humura.db → display results
- Results: alert banner (CRITICAL red, HIGH red, MODERATE amber, STABLE green) + spectrogram (Plotly heatmap with F0 overlay and healthy range 350-650 Hz dashed lines) + feature summary table + triage brief + referral letter expander + patient ledger (always visible)
- Gemini: prompt asking for 3 sections (Emergency Assessment Profile, Stabilization Steps, Referral Letter). Model gemini-flash-latest. max_output_tokens=4096. temperature=0.3.
- Rule engine fallback: 8 clinical rules checking fever, hypothermia, tachypnea, bradycardia, tachycardia, low weight, acoustic score
- dotenv: load .env file at startup
- Patient ledger: pull from SQLite, show as st.dataframe

## Critical details
- The model file cry_model.joblib should be generated by train.py which downloads from mahmudulhasan01/baby_crying_sound on HuggingFace (845 normal: hungry/burping/discomfort/tired/laugh/silence) + generates 422 synthetic distress cries
- random_state=1 gives the best validation results
- All DB writes and Gemini calls wrapped in try/except with clean fallbacks
- The app must never crash — if audio fails, show error message gracefully
